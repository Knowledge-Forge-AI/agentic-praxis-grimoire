# APG63 Markdown Language-Profile Architecture

## Outcome

APG63 begins the next Web/Node profile line after APG62's terminal CSS
rejection, without retrying or repairing `css-language-profile`. Starting
from exact APG62, it reconstructs Markdown architecture from exact source,
rights, corpus, and target evidence; defines a deliberately lean,
candidate-independent validation contract; decides the structural-policy
disposition; proposes [ADR 0037](../adr/2026/07/0037-markdown-language-profile-architecture-and-lean-validation.md)
as Proposed; authors no skill; and integrates nothing.

The authoring-eligibility result is **authoring-eligible-with-narrowing**:
the owner is coherent, sources and rights are exact and current, the
boundaries are closed, and the structural policy is complete — with the
owner narrowed as the architecture records and candidate authoring still
requiring separate authorization. Development remains 28 canonical skills,
28 catalog rows, 28 relative projections, and fourteen stable / fourteen
provisional maturity rows; ADR 0031, 0034, 0035, and 0036 remain Rejected;
public and active corrected v0.4.0 and both read-only target objects
remain unchanged.

## Sources, rights, and dogfood

CommonMark 0.31.2 (2024-01-28) and the pinned GFM specification revision
0.29 (2019-04-06) were reverified at exact objects, with both
specification documents confirmed CC BY-SA 4.0 and implementation code
terms recorded as separate non-authority. A release-tag review found no
newer CommonMark revision. Seven target Markdown documents across the two
pinned targets were reconfirmed with exact classifications: the dogfood
evidences recurring decisions (two parser contexts per repository, a
ubiquitous frontmatter boundary, GFM tables, fenced code, a
generated-changelog class, MDX siblings) but no long-document pressure
and no threshold authority.

## Architecture

The [architecture document](../architecture/markdown-language-profile-architecture.md)
defines: a narrowed coherent owner (selected-dialect document semantics);
explicit non-owners; a dialect contract (CommonMark 0.31.2 base plus
evidence-selected GFM, repository-parser precedence, MDX as separate
owner and non-trigger, frontmatter as recognized boundary); the raw-HTML,
frontmatter, and MDX/host boundaries; a semantic-risk model independent
of structural growth under the shared warning contract; and
structural-policy disposition **C** — qualitative structure-first with no
numeric whole-file bands, line count demoted to a descriptive
observation, constrained by ten purpose controls frozen (with a recorded
SHA-256) before the disposition was selected. The rejected APG56 values
are not reused, and no normative threshold is percentile-derived.

## Lean validation contract

The [lean contract](../specs/markdown-language-profile-lean-contract.md)
freezes closed owner and response-class vocabularies, a ten-field
scenario schema over exactly thirty-six scenarios (APG63-MD-001…036), the
material/ordinary/note severity model with tiered exactness (ownership,
permission/stop, and safety/rollback exact; benign bookkeeping
recommended-only unless consequence-bearing), the one-correction rule,
and the corrected-state evidence rule that preserves corrected candidate
state before terminal integration or deletion. Generic candidate
lifecycle stays outside Markdown semantic prose. CSS's sixty-row
exact-action design is deliberately not recreated.
