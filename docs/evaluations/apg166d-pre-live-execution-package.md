## Acquisition policy

The internal route has a closed argv grammar: one read-only flag and one print
flag, with the long print spelling normalized before artifact construction.
The observer may additionally provide its logging options. Caller task text
belongs on stdin. Native tool, MCP, model, settings, directory and permission
overrides, including permission routing aliases, are rejected before handoff
consumption. Ordinary profile calls retain their existing behavior.

The acquisition owner captures exactly its selected recovery files beneath the
current run's `acquisitions/skills` subtree, including support files. The wrapper
validates that inventory before emitting one native `--add-dir`. Physical
directory/file identities and complete path/size/SHA inventories are retained.
The grant is process-local and absent from ordinary static launches.

The manager authorizes default permission mode only on this validated internal
route. Its available tools are Read and the three APGR MCP tools; only those
three MCP tools are auto-allowed. No mutation tool is exposed. Default mode
therefore does not grant Bash, Write, Edit or Agent authority. One strict APGR
MCP config and isolated setting sources remain mandatory. Installed help
confirmed `--add-dir` and the additional `--permission-prompts` spelling.

Consumption remains early and exclusive. A failure before model start may burn
an attempt; replay is refused. A correction requires a fresh run/binding/attempt.
This is a same-user custody contract, not hostile-operator confinement.
