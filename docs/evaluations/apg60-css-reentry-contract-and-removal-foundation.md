# APG60 CSS Re-entry Contract and Removal-Closure Foundation

Status: Complete — executable CSS response and removal-closure contracts
frozen and tested before any candidate re-authoring.

APG60 starts from the terminal APG59 rejection. APG59 corrected five material
policy defects but then found that response outcomes, task aggregation,
semantic and authority boundaries, one-count behavior, exclusions, and
rejected cleanup were not executable enough to decide retention safely.
Retrying candidate prose immediately would have let the next candidate shape
the tests used to judge it. APG60 instead freezes candidate-independent
behavior and cleanup contracts first.

## Executable pre-authoring contract

The public-safe contract contains exactly `APG60-CSS-001` through
`APG60-CSS-060`. It keeps the rejected-evidence limits Green below 300,
Yellow 300–599, Orange 600–899, and Red at 900 or more. Those values are a
pre-authoring oracle, not current guidance.

The seven case families are:

| Family | Cases |
| --- | ---: |
| Growth transition | 8 |
| Complete-task aggregation | 10 |
| Authority | 8 |
| Semantic owner | 10 |
| One-count and exclusions | 12 |
| Legacy and exception | 6 |
| Lifecycle removal | 6 |

The standard-library reference evaluator validates a closed schema, selects
the highest baseline/current/projected/actual state, applies complete-task
aggregation, distinguishes four operation categories, resolves authority,
and returns exact required and forbidden action sets. Tests compare structured
results rather than searching for expected phrases. A deliberately misleading
Markdown control contains the complete action vocabulary but cannot satisfy
the evaluator. A separate collection check rejects a missing or reordered
case, including any omitted task-aggregation control.

The corrected accessibility boundary requires an established project
condition before CSS may classify a semantic Red violation. CSS explains its
own behavior but does not invent or finally accept accessibility requirements.
Global custom-property scope is not inherently Orange; a named ownership,
reach, fallback, inheritance, or project-token-policy defect is required.
Standalone CSS and CSS modules receive one count, embedded Astro and MDX CSS
receive semantic review without an additive count, and every frozen exclusion
class has an executable case.

## Removal closure

A versioned generic manifest distinguishes current integration surfaces,
current narrative owners, historical evidence, publication-excluded history,
and managed reports. The CSS removal plan instantiates 50 owners: 29 current
integration subowners, 11 current narrative subowners, seven public historical
owners, two publication-excluded historical owners, and one managed-report
owner.

The model includes the hard-coded project-skill and release/public-surface
owners omitted from the APG59 removal prose. Every one of the 40 current
subowners is omitted independently from a retained synthetic candidate and
left stale independently after synthetic rejection; each mutation must fail.
Historical owners must survive cleanup. Surviving references must resolve to a
retained owner or an explicit project-owned fallback.

Exact APG58/APG59 Git history is used read-only to prove that APG58 authored
the candidate, APG59 removed its current leaf and specification, and the ADR
and evaluation history survives. A real disposable `git revert --no-commit`
of APG59 restores candidate surfaces and is rejected as cleanup. No live
candidate or target is created or mutated.
