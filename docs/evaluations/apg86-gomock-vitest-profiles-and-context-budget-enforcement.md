# APG86 GoMock and Vitest Profiles with Context-Budget Enforcement

## Recovery and candidate result

The original APG86 plan and independent post-plan review completed, but the
first work process was terminated by provider transport before it produced a
candidate. Replacement work treated the surviving working tree as
authoritative, retained only coherent bytes, and completed the same canonical
phase without repeating planning or invoking another reviewer.

The replacement candidate accepts ADR 0048 with amendment and provisionally integrates exactly
`gomock-test-profile` and `vitest-test-profile`. Development is 35 canonical
skills, 35 catalog rows, 35 exact relative projections, and 35 discoverable
skills, with 14 stable and 21 provisional rows and no malformed metadata.

## Profile boundaries and sources

`gomock-test-profile` is calibrated to Uber GoMock v0.6.0. Official tagged
README and package documentation establish source, package, and archive
generation modes; controller cleanup and single-finish behavior; unordered
expectations unless `InOrder` or `After` supplies a dependency; call-count,
matcher, action, and diagnostic behavior. The Apache-2.0 upstream expression is
not copied. APG uses factual API identifiers and independently written
synthesis, and requires refresh when the selected release or those behaviors
change.

The Go testing owner graph now has three direct component siblings without a
stack owner. Public-safe APG86 scenarios route controller and expectation
questions to GoMock, table and subtest lifecycle to native Go testing, value
diffs to go-cmp, and interface semantics to Go.

`vitest-test-profile` is calibrated to the official Vitest 4.1 documentation
and tagged v4.1.7 sources. Those sources distinguish root and project
configuration, environments and pools, assertions, transformed module mocks,
timers, concurrency and isolation, snapshots, and coverage providers. Vitest
is MIT licensed; APG copies no upstream prose, code, examples, tables, or
diagnostics. Release-sensitive behavior requires refresh when the selected
Vitest line changes.

Vitest scenarios route runner mechanics to the new profile, ECMAScript and
TypeScript semantics to their language owners, Node event-loop behavior to the
runtime owner, test sufficiency to `implementing-with-test-discipline`, React
component behavior to the future React owner, and coverage thresholds to
project policy.

## Limitations and stop

This phase validates APG's reusable profile and integration contracts; it does
not install GoMock or Vitest, run `mockgen`, execute a target runner, mutate a
snapshot, or establish target-specific runtime evidence. The post-plan review
is complete, while the dispatcher-owned pre-final review remains external to
this candidate and is not self-attested by the tracked records.

No remote push, publication, deployment, target mutation, advisory discovery,
or APG87 work is authorized or performed.
