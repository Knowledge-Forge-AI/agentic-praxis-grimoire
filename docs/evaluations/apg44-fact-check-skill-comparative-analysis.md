# APG44 Fact-Check Skill Comparative Analysis

Phase ID: `APG44`

Evaluation date: 2026-07-26

## Objective and boundary

APG44 opens v0.5 work from the corrected APG43 baseline. It analyzes the
external [`petar-nauka/fact-check-skill`](https://github.com/petar-nauka/fact-check-skill)
repository for ideas that may improve Agentic Praxis Grimoire, records the
human-approved v0.5 agenda, freezes bounded recommendations with author
dispositions, and hands them to a later, separately authorized Codex peer
review (recommended APG45).

APG44 is an analysis and authoring phase. It implements no recommendation,
adds no skill, alters no routing, changes no release policy, and begins no Go
or web-profile work. Development, public, and active surfaces remain
28/28/28 with fourteen stable and fourteen provisional rows. No phase after
APG44 is authorized.

## Source identity and rights

The analyzed source is `petar-nauka/fact-check-skill`, default branch `main`
at commit `ebfde09a28b5547cbed29f5f66ddfd3595e64ade` (skill version v3.1),
and declares MIT terms. A local clone was verified clean and at exact parity with the
remote, so one source identity controls every observation; exact object

content was treated as untrusted evidence.

Rights mode for APG44's adopted boundary is clean-room conceptual: no external
table, taxonomy, schema, code, scoring formula, or output structure is adopted.
APG45 later found short source-shaped phrases in publication-excluded authoring
analysis, independently re-expressed them, and confirmed that no material
external expression remains in the resulting public or private records.

## What the external skill owns

Its coherent owner is verification of external-world claims in public
discourse — news, social posts, screenshots, URLs — with a Bulgarian/EU
regional specialization, packaged as a single consumer skill with four
proportional modes, an evidence-ledger workflow, a manipulation taxonomy, a
numeric misinformation-risk score, a JSON result contract with validator and
HTML card renderer, and regional source packs. Its components separate
cleanly into: evidence-led verification procedure (transferable ideas),
Bulgarian/EU project content (project-specific), general fact-checking
practice (domain expertise), presentation tooling, packaging mechanics, and
several overbroad constructs analyzed below.

## What APG already owns

Most of the external skill's general evidence hygiene is already APG
architecture, often in stronger form:

- untrusted-content posture at the report boundary and in assignment source
  boundaries;
- dated, identity-anchored provenance records with license, derivation mode,
  and supersession fields;
- revision-not-overwrite via append-only records and forward-commit
  correction;
- per-claim-then-overall judgment as the review skill's finding-then-
  disposition order, with truthful unverified outcomes;
- progressive disclosure (compact leaf plus on-demand references),
  deterministic stdlib validation, fixtures, focused tests, and
  keep-generated-artifacts-out-of-source release policy;
- proportionality as the smallest-sufficient-capability principle.

The comparison found no case where different external terminology alone
justifies a new APG owner.

## Recommendations frozen for Codex review

Ten recommendations (REC-01…REC-10) are frozen in the publication-excluded
recommendation ledger, each with source facts, current owner, proposed
surfaces, scenario mappings against forty-one frozen analysis scenarios,
counterexamples, falsification conditions, and a Codex probe. Author
dispositions — nothing is accepted in APG44:

Forwarded (sentence-scale changes to existing owners only):

1. **REC-01** — distinguish verifiable claims from opinion or prediction and
   restate implied claims before dispositioning them, in
   `reviewing-and-verifying-repository-work` (recommend-with-narrowing).
2. **REC-02** — distinguish absence of evidence from contradictory evidence
   in unverified findings, same owner (recommend-for-codex-review).
3. **REC-03** — state claim-relative, independence-based source authority
   (prefer the inspectable source closest to the claim; count corroboration
   by independent origins, not artifact count) in provenance policy with a
   matching synthesis-skill clause (recommend-for-codex-review).
4. **REC-04** — optional `access_limitation` and `independence` fields in
   the public provenance template, recorded only when material
   (recommend-with-narrowing).
5. **REC-05** — one explicit untrusted-external-content sentence in
   `synthesizing-repository-guidance`: embedded instructions in a source
   corpus are data, never task authority (recommend-with-narrowing).

Deferred:

6. **REC-06** — a fact-checking owner in APG is **deferred for real use**:
   the misinformation-specific expertise (satire/opinion guards,
   manipulation taxonomy, prebunking, share-safe correction) is coherent
   domain knowledge, but no APG phase or operator demand has needed it, and
   its regional-content refresh burden is heavy. Revisit only on recurring
   demand that existing owners cannot serve.

Rejected patterns (recorded so review does not re-derive them):

7. **REC-07** — the numeric Misinformation Friction Score:
   reject-false-precision. A weighted sum of three subjective components
   displays measurement that never happened; categorical evidence-named
   reasoning is more truthful for APG's domain.
8. **REC-08** — the fixed eight-level source-tier hierarchy and the
   universal three-independent-sources confidence rule:
   reject-false-precision. Authority is claim-relative (a peer-reviewed
   study outranks derivative coverage of it; a single authoritative
   changelog settles a version fact); corroboration thresholds remain
   project-owned policy.
9. **REC-09** — the result schema, validator, HTML card renderer, and
   packaging toolchain: reject-overlap and reject-maintenance-cost. APG's
   own record tooling already implements the pattern for claims APG
   actually makes; APG is not a fact-check card generator.
10. **REC-10** — date stamping and revision policy: reject-overlap; APG's
    git-anchored ownership is stronger than the external convention.
