defaults and the APG28A-adopted testing and reporting architecture. It adds no
duplicate skill and changes no trigger, maturity row, catalog description,
capability-map entry, projection, or release identity.

## Project-owner alignment

Repository instructions, structured defaults, testing policy, manager-worker
protocol, skill maintenance, project model, provenance, and roadmaps now use the
same scoped-test, coverage-remediation, boundary, evidence, and compression
defaults. The agent-reporting architecture already owned the required Git-show,
Git-diff, and associated operational forms and remains behaviorally unchanged.

## Boundary

APG29 changes no pytest threshold or runner behavior, release surface identity,
ChatGPT canonical path, personal skill, target repository, public or active
v0.3.0 object, or future profile. No v0.4.0 release or successor phase begins.
