# APG59 CSS Language-Profile Validation and Integration

## Outcome

APG59 preserves the exact APG58 authoring object, independently verifies its
reports and remote delivery, and validates the CSS pilot against exact source,
rights, and read-only target evidence. Failing-first executable contracts
reproduce five material defects. One coherent forward correction improves the
candidate policy, but fresh independent corrected-state review finds new
material verification and removal defects. Under the one-correction rule,
[ADR 0035](../adr/2026/07/0035-css-language-profile-and-policy-selected-structural-limits.md)
is **Rejected** and the current candidate surfaces are removed.

Development remains 28 canonical skills, 28 catalog rows, 28 relative
projections, fourteen stable and fourteen provisional rows, twenty-six general
routes, one ChatGPT-local route, and twenty-seven checked route edges.
Corrected public and active v0.4.0 remain unchanged.

Subsequent foundation: APG60 preserves this terminal rejection and converts
the corrected-state executable/removal defects into a frozen 60-case
pre-authoring oracle and complete retained/rejected removal-closure model. It
does not change APG59's result, restore the candidate, or authorize a
successor.

## Independent verification

The CSSWG source pin and repository-level W3C Software and Document License
were reverified from exact bytes; document headers and third-party material
remain separate. The two target repositories were inspected through exact Git
objects only. An independent UTF-8/BOM-aware, universal-newline counter
reproduced all twelve nonblank counts: nine Green, two Yellow, zero Orange,
and the 995-line legacy control Red. Four embedded Astro style contexts were
identified without an additive CSS count. Neither target was mutated or
executed.

## Initial findings and correction

The initial focused run produced five failures and three passes:

- M1: APG58 classified present size without projected and actual resulting
  counts.
- M2: growth lacked a complete-task aggregation boundary.
- M3: accepted repository and bounded human authority were incomplete.
- M4: accessibility-related Red examples did not first require an established
  project condition.
- M5: global custom-property scope could be overclassified Orange.

The single correction added baseline/current/projected/actual-result
classification, task aggregation, anti-salami-slicing definitions, explicit
instruction precedence, an accessibility acceptance boundary, and narrower
custom-property escalation. It kept 300/600/900 unchanged because no direct
material numerical contradiction was found.

## Corrected-state rejection

Fresh non-author review found that the public-safe tests did not execute the
required response outcomes, evaluated only one of six task-aggregation cases,
left semantic and exclusion cases primarily as phrase checks, did not apply
the corrected accessibility rule to the frozen scenario outcome, and did not
exercise rejected cleanup. The documented removal path also omitted hard-coded
project and release owners, so following it would leave stale references.

These are material retention defects discovered after the single correction
pass. APG59 therefore makes no second behavior correction. The leaf,
specification, fixture, focused test, projection, catalog row, route,
project-skill owner, release entry, and test-inventory owner are absent from
the terminal state.

ADR 0031 and ADR 0034 remain Rejected. Every Web/Node candidate remains
deferred. No target build, test, lint, preview, browser, deployment, readiness,
publication, active deployment, migration, or successor phase was run.
