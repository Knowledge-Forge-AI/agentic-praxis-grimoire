# APGR v0.10 consolidation roadmap

This documentation covers v0.10.0.

## Direction and authority

v0.10 is a consolidation release built on the six frontend capability slices.
Preceding releases v0.9.0 and v0.8.1 remain frozen. The historical sequence
leading to v0.10.0 is preserved below. No new capability leaf, maturity promotion, consumer mutation, or
host activation is authorized here.

APG122 foundation/SVG, APG123 Browser/UI and APG124 Toolchain are manager accepted.
The original APG125 dispatch remains provider-blocked after Astra capacity failure.
APG126 qualifies the preserved Browser Runtime and Composition candidate without
replaying implementation. APG126 is manager-accepted after exact-tree recovery;
its original dispatcher aggregate remains historically blocked with
`PATH_DISPOSITION_INVALID`.
The [APG126 evaluation](evaluations/apg126-preserved-browser-candidate-and-backlog-consolidation.md)
retains this distinction and the consumer limitations.

## Capacity and ownership

[ADR 0053](adr/2026/09/0053-v0-10-discovery-capacity-and-svg.md) preserves the
historical 9,527-byte integrity control and the six 330-byte reservations.
Current `v0.10-browser-runtime` has 45 canonical/catalog/projection/discoverable
leaves, 14 stable and 31 provisional. Descriptions total 11,142 UTF-8 bytes under
11,507, leaving 365 bytes. All 44 pre-APG125 descriptions remain frozen. No unused
named reservation remains; unknown leaves are rejected independently of headroom.

SVG owns vector authoring; Playwright owns runner mechanics; accessibility owns
semantic and testing hierarchy; Vite owns build/dev behavior; npm owns package
management; browser runtime owns browser-host semantics. Existing language,
component and Node owners retain their domains. Descriptions, selected context
and provider overhead remain distinct measurements.

## Consumer and external boundaries

APG124 acceptance preserves its historical consumer failures. Retained APG125
producer evidence includes 177 passing studio tests and one compiler-version
assertion mismatch; APG126's fresh consumer metadata inspection does not establish
later-source runtime parity or causality. Desktop browser and host-unavailable
fallback evidence does not qualify actual Tauri/WebView or assistive technology.
JACA CI/XO adoption and Repo Map product qualification remain consumer-owned under
their current contracts. APGR controls no external runtime or deployment here.

## Repo Map support milestones

The [Repo Map support roadmap](repo-map-support-roadmap.md) is part of the

specialized-profile schedule. Reusable v0.10 support is distinct from future
protocol and graph-quality guidance, storage/migration composition and
