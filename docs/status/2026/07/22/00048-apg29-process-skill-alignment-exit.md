## Scope and result

APG29 applies one bounded correction to each of four existing skills. The
implementation owner gains useful-contract coverage remediation and its stop;
the planning owner gains scoped evidence and justified expansion; the review
owner gains honest coverage, mock and real-boundary, and Git/operational
evidence checks; and the roadmap-assignment owner retains compression without
assuming broad suites.

All 51 frozen scenarios match. Names, triggers, maturity rows, catalog
descriptions, capability-map entries, projections, and the 21/21/21 development
skill shape remain unchanged. No new ADR is needed because ADRs 0020, 0021,
0023, and 0024 already own the decisions.

## Validation and review

Focused tests cover each changed skill contract, and the public evaluation
records every frozen scenario. Directly affected inventory, release-policy,
skill-library, record-identity, compilation, Markdown, link, privacy, and
whitespace checks are phase gates. Fresh reviewers cover coverage remediation;
scoped testing and mock/integration boundaries; formal and non-phase defaults;
manager prompt compression; and the complete diff.

The combined and full suites are deliberately not default APG29 gates. APG29
does not change test infrastructure, and no focused failure justifies that
expansion.
