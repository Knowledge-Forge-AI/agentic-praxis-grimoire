## Decision

1. A reusable `javascript-language-profile` owns a narrower ECMAScript
   core: normative language semantics for a concrete JavaScript region
   after the source goal, concrete host context, emitted bytes, and
   applicable implementation facts are established.
2. Source-goal selection, feature availability, runtime conformance,
   engine divergence, Node CommonJS and resolution, browser/DOM/Web
   APIs, ECMA-402, TypeScript, JSX, tool behavior, repository
   permission, security acceptance, project support policy, and
   deployment are explicit non-owners with typed receiving owners.
3. Authority is question-specific: source goal and concrete host,
   emitted-byte availability, observed runtime behavior, divergence and
   compatibility, and permission each have their own authority, and a
   scenario may bind several typed authorities without collapsing them
   into one composite token.
4. Semantic, structural, policy, and effective decisions are four separate
   layers. Effective response is the maximum active severity; permission is
   stopped by Red and unresolved by an open policy decision; no layer silently
   overwrites another.
5. Per-layer routes name unresolved receivers. The effective route union is
   only a receiver summary; provenance-bearing effective obligations preserve
   every layer/source/route position, including two questions to the same
   receiver.
6. Normative, context, and policy authorities are separate typed
   fields; a consequence-bearing authority may not appear only in
   prose.
7. The layered contract — not any register — owns every closed
   vocabulary. Semantic scenarios carry no structural signals;
   structural controls carry no semantic outcome oracle; composition
   rows alone test precedence and simultaneous routing; two process
   rows stay outside candidate prose.
8. The corrected registers are exactly APG69-JS-S001–S033 (eighteen fields),
   ten structural signals (ten fields), APG69-JS-C001–C015 (twenty-four
   fields), and APG69-JS-P001–P002 (five fields). Every semantic row types its
   artifact class, source goal, host, authorities, routes, and rollback; a
   non-concrete input never produces a host-specific result.
9. Correctness that depends on unspecified collection or finalization
   timing is Red (`stop-and-escalate`).
10. Structural policy is qualitative disposition C. Multiple active signals
    use the maximum response while retaining signal-owned routes, obligations,
    and rollback; inactive false-positive controls cancel only their own
    signal. Context route rules resolve exact host/resolution receivers. No
    numeric whole-file band or corpus-derived threshold exists.
11. JavaScript-to-TypeScript migration is project-owned: the profile
    identifies `data-shape-contract-pressure` and routes to
    `project-design` and `typescript-owner` without deciding migration
    or defining "large" numerically.
12. Artifact class is typed before consequence. Produced-artifact direct-edit
    permission is repository-owned; provenance, regeneration, and
    transformation remain exact-owner questions.
13. Applicable repository/security policies compose conjunctively. Human
    supersession is exact-scope only; bounded exceptions carry authority,
    scope, rationale, evidence, validation, and rollback, and overrun stops.
14. Corrected-state eligibility is `not-applicable-rejected`. Fresh APG70
    review found new material defects after the sole correction; no second
    semantic correction is permitted.
15. APG69/APG70 author no skill and change no integration owner: no
    JavaScript projection, catalog row, maturity row, route, project,
    release, fixture, or test surface exists or changes, and the
    Markdown candidate remains retained provisional.
16. APG70 terminally rejected this ADR. APG71 is not recommended and no
    successor is authorized.
