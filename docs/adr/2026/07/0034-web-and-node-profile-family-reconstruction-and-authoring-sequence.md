# ADR 0034: Web and Node Profile-Family Reconstruction and Authoring Sequence

- Status: Rejected
- Date: 2026-07-29
- Proposed in: APG56
- Decided in: APG57
- Relates to: ADR 0029 (Accepted with amendment; unchanged),
  ADR 0031 (Rejected; unchanged), ADR 0032 (Accepted), ADR 0033 (Accepted)

## Context

APG50 proposed a ten-candidate Web/Node family, APG51 rejected ADR 0031,
and APG52 created exact-object reproducible evidence. APG56 made a fresh
reconstruction and proposed this ADR. APG57 independently verified the
evidence, applied its one permitted coherent correction, and submitted the
corrected state to fresh non-author review. This ADR neither reopens nor
amends rejected ADR 0031.

Owner validity, authoring eligibility, and growth-band eligibility were
reviewed independently. A coherent owner did not grant authoring or
numeric-policy authority.

## Decision

ADR 0034 is **Rejected**. The corrected-state package failed the mandatory
review gate after the one authorized correction cycle. APG57 does not repair
the new defects through a second architecture or numerical correction.

The attempted corrected ledger recorded CSS and MDX as valid owners and the
other eight owners as valid with narrowing; zero authoring-eligible, eight
deferred-evidence, and two deferred-policy; and no accepted numeric band.
Those rows remain review evidence, not accepted architecture. The ledger also
assigns the single deferred JSX/TSX whole-file class in both the TypeScript
and JSX rows without clearly distinguishing TypeScript's non-additive
semantic route, so the terminal one-count ownership is ambiguous.

The attempted correction exactly reproduced APG56's eight proposed numeric
values and selected TypeScript configuration option D, but its compact
reviewer output is not trustworthy enough for acceptance:

- target samples are labeled individually complete when row count happens to
  equal target count, even though exact individual placement is unavailable;
- threshold intervals omit minimum/maximum constraints for interior
  thresholds and therefore emit bounds contradicted by the compact evidence;
- the executable exact-reproduction gate compares thresholds or base
  ineligibility rather than the complete APG56 class projection; and
- focused tests do not exercise these required truthfulness branches.

The five APG57 supplemental scenarios also omit the established
input/selection/non-selection/project/semantic/growth/source/action/rollback
fields, and the broad-owner scenario names no concrete owner. These are
material corrected-state architecture and evidence defects.

Independent review otherwise confirmed important non-terminal evidence:

- APG56's proposal table mechanically contained six proposed eligible and
  four deferred candidates, not the repeated five/five prose;
- JavaScript, TypeScript module, and Node proposed bands fail mapped
  monster-file purpose controls;
- TypeScript declaration, CSS, and Astro show tail or
  leave-one-family-out instability;
- Markdown and TypeScript configuration physical-line metrics are
  unsuitable without separately frozen structure;
- scoped CSS, JSX/TSX, and MDX lack sufficient balanced evidence;
- TypeScript configuration option D is the reviewed direction:
  project-owned structural growth with TypeScript semantic ownership;
- React and Vitest remain under ADR 0029 Policy A;
- browser/DOM runtime, generic HTML, and accessibility remain separate
  evidence gaps;
- Starlight, package managers, bundlers/Vite, lint/format, deployment,
  browser support, visual design, and content strategy remain project-owned;
  and
- every physical file must have at most one whole-file growth owner, with
  embedded languages only non-additive semantic routes.

No numeric band, owner graph, authoring candidate, scenario supplement, or
slice sequence is accepted by this rejected ADR. There is no eligible
authoring slice. W1–W4 remain deferred, and the combined
JavaScript/TypeScript/Node W3 batch is not authorized.

## Sources, rights, and preservation

The factual review keeps source, documentation, and rights grants separate.
Both targets resolve Astro 7.1.3 while the website declares `^7.0.2`.
TypeScript source/packages are Apache-2.0 while website/handbook material is
CC BY 4.0; only the theme's TypeScript 5.9.3 Astro-check path is a verified
effective consumer, while website TypeScript 7.0.2 is package/bin-present
without a tracked consumer.

The theme's original baseline carries `LICENSE-MIT`; exact post-baseline
additions and modifications carry an AGPL-3.0 notice, package metadata says
AGPL-3.0-or-later, and commercial, NOTICE, and CLA surfaces remain separate.
The website grants no reuse license and is measurement-only. No upstream or
target expression enters APG guidance.

React and Vitest Policy A, generated/derived exclusions, semantic-risk
independence, legacy smallest-safe-fix behavior, project-owned boundaries,
and the prohibition on mandatory skill chains remain prior constraints, not
newly accepted content of ADR 0034.

## Consequences and re-entry

All ten candidates and every claimed band remain deferred. No skill, catalog
row, projection, route, maturity state, test inventory, dependency, fixture,
executable, release row, or active integration is accepted or changed.
Development remains 28/28/28 with fourteen stable and fourteen provisional
skills; corrected public and active v0.4.0 are unchanged.

A future attempt requires separately authorized evidence and architecture
work that starts fresh from the recorded defects. It may not treat the APG57
reviewer output, attempted ledger, or supplemental scenarios as accepted
inputs without independent correction and review. No ADR 0035 is created and
no successor begins.
