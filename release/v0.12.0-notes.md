# APGR v0.12.0 candidate notes

Status: **unreleased; public staging candidate prepared; staging and PR unperformed**.

The candidate retains 45 canonical skills, 14 stable and 31 provisional, and
the existing package and Go module identities. No new skill or maturity
promotion is included. The 11,142-byte description corpus remains under the

## Candidate changes

- Architecture transfer of the lightweight single-phase execution runtime from Agent-Central into permanent APGR ownership.
- Decoupled semantic role graph, flexible actor binding, Request V2 work-only protocol, and non-daemon SQLite persistence (`<APGR_HOME>/state/dispatcher.sqlite3`).
- Provider parity closure across Codex, Claude, and Antigravity, operational observation collection, telemetry monitoring, and cooldown state machines.
- Request V2 multi-turn execution coordinator, pre-launch attempt error boundary, and auxiliary attempt accounting.
- Public Go domain packages (`phase`, `routing`, `evidence`, `candidate`, `provider`) and JACA XO qualification handoff without duplicate Go execution runtime.
- Operator outbox projection engine (`<outbox_root>/<project>/<phase-id>/`) and truthful Git repository finalization across `checkpoint`, `commit-local`, and `publish` policies.
- Provider failure feedback, high-confidence quota failure classification, and bounded dynamic rerouting ($M=3$) with substantive work integrity boundary.
- Request V2 Turn 5 terminal result-repair engine with exact byte identity, fail-closed persistence, and auxiliary attempt lineage protection.
- Release operator hardening: numeric draft release ID binding, durable release authority reconciliation when public main advances (ADR 0068), GitHub Actions Trusted Publishing alignment, npm platform-before-launcher state machine, resumable multi-channel receipts, and automated Homebrew formula generation.

## Qualification and release boundary

Local candidate builds and checks do not publish packages. Public staging
discloses its contents, so confidentiality, rights, exact projection, and
private-history checks precede its push. The future promotion uses `staging`
→ PR → squash merge to `main` → release. Actual merged source and commit-bound
artifacts must be qualified before tagging and publication.

`public_staging: not_started`; `public_pr_ci: not_run`; `public_release: not_started`.

Use a source checkout or locally qualified candidate packages while v0.12.0
is unreleased. v0.11.0 remains the published version across GitHub Releases,
Go, PyPI, npm, and Homebrew tap. See
[distribution guidance](../docs/distribution.md) and the
[release procedure](../docs/public-release-process.md). Cross-built Linux
artifacts are not evidence of Linux execution or full developer qualification.
