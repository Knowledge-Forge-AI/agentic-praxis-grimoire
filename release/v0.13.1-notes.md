# APGR v0.13.1 candidate notes

Status: **PENDING; unpublished candidate**. v0.13.1 is not tagged, published,
natively qualified or hosted-CI tested, and it is not available on any
registry.

v0.13.1 is a patch release. Its predecessor is v0.13.0. It carries the same
46 canonical skills (14 stable and 32 provisional), dispatcher, RTK integration
and first-party Nix flake described in the [v0.13.0 notes](v0.13.0-notes.md),
with patch packaging and Vite fixture/profile corrections. Package names and
the Go module identity are unchanged.

## Correction

- **Darwin minimum-version declaration.** The v0.13.0 Darwin ARM64 wheel is
  tagged `macosx_11_0_arm64`. A retained actual-byte inspection of the v0.13.0
  Darwin binary observed a declared minimum macOS 12.0 and SDK 12.0 despite
  that tag. This is byte inspection only, not native execution evidence, and
  no compiler cause is claimed.
- **Corrected tag and requirement.** The v0.13.1 Darwin ARM64 wheel is tagged
  `macosx_12_0_arm64` and requires macOS 12 (Monterey) or later.
- **New seam check.** Every release seam (the builder, the Python backend, the
  npm packager, prebuilt publication and distribution-candidate validation)
  now checks the actual Mach-O minimum against the wheel tag and refuses a
  binary that requires more than macOS 12.0.
- **Linux targets are unchanged.** The wheels remain
  `manylinux_2_17_x86_64` and `manylinux_2_17_aarch64`.

## Published v0.13.0 assets stay frozen

v0.13.0 was published. Its GitHub Release carries its assets (three wheels,
the sdist, npm tarballs, binaries, manifests and `SHA256SUMS`), and PyPI lists
its two Linux wheels and the sdist. Its original Darwin wheel is present on
GitHub but absent from the PyPI listing. Those published assets are never
renamed, replaced, overwritten, yanked or deleted. No npm or Homebrew
availability of v0.13.0 is claimed. v0.12.0 remains the latest release proven
across GitHub Releases, Go, PyPI, npm and Homebrew tap.

## Release shape

Release topology is unchanged: eleven distributables (three binaries, three
wheels, one sdist and four npm tarballs). With three binary manifests, the
distribution manifest and `SHA256SUMS`, that is sixteen flat release files; the
sealed bundle adds a seventeenth seal file. v0.13.1 assets use their own
v0.13.1 namespace, for example
`agentic_praxis_grimoire-0.13.1-py3-none-macosx_12_0_arm64.whl`,
`agentic_praxis_grimoire-0.13.1-py3-none-manylinux_2_17_x86_64.whl`,
`agentic_praxis_grimoire-0.13.1-py3-none-manylinux_2_17_aarch64.whl` and
`agentic_praxis_grimoire-0.13.1.tar.gz`, with the npm launcher and three
platform packages at 0.13.1.

## Release boundary

Release authority for v0.13.1 is a closed, explicit patch route with
predecessor v0.13.0. Governance is approval-only: there is no review-only
waiver, and the v0.13.0 PR #3 waiver is not inherited. The staging PR number,
head and base, tested merge, runs and jobs, approval, squash commit and tag
are measured at release time and authenticated by live GitHub readbacks.
v0.14.0 and unknown versions are refused. The fixed v0.13.0 publisher and
admission contract needs its own separate bounded correction and is not part of
this patch.

Nothing here is native, hosted-CI, macOS 12 or publication evidence. Use a
source checkout or locally qualified candidate packages until v0.13.1 is
actually published. See [distribution guidance](../docs/distribution.md) and the
[release procedure](../docs/public-release-process.md).

## CI tool dependency review

Risk review dated 2026-10-21. This is a temporary CI-tool risk disposition. It
is not a vulnerability fix and not a claim of dynamic unreachability.

The static lane installs Semgrep 1.179.0, which requires MCP 1.29.0 exactly.
The dependency audit reports CVE-2026-59951 / GHSA-84m7-p3x7-pcfv for that
transitive CI-tool package. The upstream advisory concerns stateful Streamable
HTTP sessions that retain initialization payloads; see the
[upstream advisory](https://github.com/modelcontextprotocol/python-sdk/security/advisories/GHSA-84m7-p3x7-pcfv).
MCP 1.30.0 contains the upstream fix. Published stable Semgrep releases checked
through 1.182.0 on 2026-10-21 still require MCP 1.29.0 exactly, so no
compatible released upgrade was observed. Forcing an MCP override, removing the
tool, ignoring the advisory or weakening the auditor is not part of this
disposition.

The maintained Semgrep invocation scans committed local rules with metrics
disabled; it does not launch an MCP HTTP server. This command-level fact does
not prove that the vulnerable functionality cannot be reached.

The exception in `tools/ci/dependency_exceptions.json` covers only MCP 1.29.0 in
the `ci-tools` inventory and the two named advisory identifiers. Runtime and
test inventories remain fully audited and cannot use it. It expires on
2026-10-28 (inclusive calendar date). Remove it earlier at the first compatible
Semgrep release accepting a patched MCP version or at any MCP HTTP-server use,
whichever occurs first. Do not renew it automatically. The raw finding stays
recorded in `excepted_vulnerabilities` with its advisory, expiry and review
reference, unrelated findings still block, and the audit is not described as
vulnerability-free. There is no scanner suppression and no PR or release-gate
waiver.

The focused tests and fresh hosted checks of the changed candidate have not run
for this change. Eligible PR approval and every other release gate remain
required.
