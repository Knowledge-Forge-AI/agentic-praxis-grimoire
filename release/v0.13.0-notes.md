# APGR v0.13.0 candidate notes

Status: **unreleased; local release candidate prepared; public staging, hosted
CI and publication not performed**.

v0.13.0 is an early pilot release. It carries 46 canonical skills: 14 stable
and 32 provisional. The 11,410-byte description corpus stays under the
11,507-byte discovery ceiling. No maturity promotion is included, and skill
promotion is not a release prerequisite. Package names and the Go module
identity are unchanged.

## Candidate changes

- **Independently usable dispatcher.** APGR is the forward single-phase
  dispatcher and needs no Agent-Central checkout. V1 and V2 normal routes are
  supported. User work, including the real Git index and staged intent, is
  preserved. Failures are diagnosable from retained run evidence.
- **Review-stage mutation policy.** Worktree mutation during review is
  `block`, `warn` (the shipped default) or `allow`. Index and HEAD mutation
  remain `block`.
- **Operator home and hosting seams.** The `apgr-home-layout-v1` home is
  resolved from `--apgr-home`, then `APGR_HOME`, then `~/.apgr`. It adds typed
  Go DTOs and a versioned SQLite schema contract for hosting orchestrators.
- **Optional RTK integration.** RTK is declared, never required. This release
  adds a read-only doctor and the provisional `rtk-command-proxy` skill.
- **Context management pilot.** Static context remains the shipped default.
  `mode = "adaptive"` is an explicit, reversible, experimental opt-in. On the
  ordinary Claude route it delivers planner-selected skills with late
  acquisition and a stage-scoped projection of the standing instructions. Other
  routes keep static transport and state why. Dogfood established the
  projection at the launcher boundary on all five Claude stages. It did not
  measure provider tokens or total context, and no saving is claimed.
- **Operational observations.** Optional per-attempt dispatch observations
  and provider-free `apgr dispatcher observations` summary, list, explain,
  index and feedback commands.
- **First-party Nix.** The repository root carries a flake that installs the
  portable `apgr` and the installed dispatcher runtime from the tag:
  `github:Knowledge-Forge-AI/agentic-praxis-grimoire/v0.13.0`. This is not an
  upstream nixpkgs package. Installed mode runs only from a write-protected
  `/nix/store` object and verifies its recorded digest when a `dispatch`,
  `finalize` or `ownership` run starts. The declared
  systems are `aarch64-darwin`, `x86_64-linux` and `aarch64-linux`.
  `aarch64-linux` has evaluation evidence only.

## Qualification and release boundary

Local candidate builds and checks do not publish packages. The promotion route
is `staging` → PR → squash merge to `main` → release. Fifteen hosted checks
gate it, including `nix (x86_64-linux)` and `nix (aarch64-darwin)`. Merged
source and commit-bound artifacts must be qualified before tagging. v0.13.0 is
not fully published until the tagged Nix readback succeeds after the GitHub
Release, Go, PyPI, npm and Homebrew channels.

`public_staging: not_started`; `public_pr_ci: not_run`; `public_release: not_started`;
`nix_tag_readback: not_run`.

Use a source checkout or locally qualified candidate packages while v0.13.0
is unreleased. v0.12.0 remains the published version across GitHub Releases,
Go, PyPI, npm and Homebrew tap. See
[distribution guidance](../docs/distribution.md) and the
[release procedure](../docs/public-release-process.md). Cross-built Linux
artifacts are not evidence of Linux execution.

Codex parent profiles now select GPT-6.1 Sol with xhigh reasoning. Stages with
the standard Gemini/Luna capability receive three independent pools of four
Gemini, Luna and Sonnet 5.5/high leaves. Worker-disabled and Gemini-only routes
retain their boundaries. Claude parents use native Sonnet; Codex and Gemini
parents use external Claude transport. Historical two-pool runs retain their
pinned configuration.
